Mouse-opened lists look the same every time.

## Fixed
- **The first opened list had a thick focus frame.** The first time a select list (or menu, or date picker) was opened with the mouse after page load, the selected item showed the keyboard focus frame. After one choice, reopening showed no frame. Popups move focus in script when they open, and browsers paint that first scripted focus as keyboard focus.
- New optional **input-modality hook**: `data-tm-input="pointer" | "key"` on `<html>`. With it, items in a list opened by mouse show only the selection fill, and a select clicked open shows no lift. The first key press (arrows, Enter, Tab) brings the focus frame back. The CSS ships in `the-mechanics.css`; it does nothing until the hook is set.

## Apply in your app (the installer does not update this code)
Add once at start-up, in the same script that sets up the select fallback (`tm-select.js` or similar):

    (function trackInputModality() {
      const root = document.documentElement;
      const set = (v) => { if (root.dataset.tmInput !== v) root.dataset.tmInput = v; };
      document.addEventListener("pointerdown", () => set("pointer"), true);
      document.addEventListener("keydown", (e) => { if (!["Shift", "Control", "Alt", "Meta"].includes(e.key)) set("key"); }, true);
    })();

Reference: `trackInputModality()` in `src/playground/lib.js`. The rule is in DESIGN.md (Focus), the skill (`references/rules.md` §5) and `docs/distribution.md` (public contract).

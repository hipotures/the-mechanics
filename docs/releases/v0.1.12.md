Native Android port. The CSS, JavaScript and skill are unchanged from v0.1.11, so web apps have nothing to update.

## Added
- **`android/`: The Mechanics for Jetpack Compose (Material 3).** Add the repository to an Android app as a git submodule and point the app's `java` and `assets` source directories at `android/kotlin` and `android/assets`. Then wrap the content in `TheMechanicsTheme(theme = …)`. See [android/README.md](https://github.com/hipotures/the-mechanics/blob/v0.1.12/android/README.md).
  - `TmColors.kt` is generated from `themes.css` by `scripts/build-compose.mjs` (`corepack pnpm build:compose`, also run by `corepack pnpm build`). It holds all three themes with the same role names as the `--tm-*` tokens.
  - `TheMechanicsTheme.kt` holds the geometry and type scale from `tokens.css` (1 px = 1 dp), the Material 3 color, shape and typography mapping, the state tones and a hard-shadow modifier.
  - IBM Plex Sans / Mono 1.1.0 TTF files, unmodified, from the official IBM/plex releases (OFL-1.1).
  - The README covers the rules the tokens can't carry (three-level borders, badges vs. status plates, focus lift, touch targets) and the known gaps: no ready-made Compose components, and the Material 3 `Switch` shape can't be changed.

## Apply in your app
- Web apps: nothing to do.
- Android (Compose): `git submodule add https://github.com/hipotures/the-mechanics.git third_party/the-mechanics`, check out `v0.1.12`, then follow `android/README.md`.

## Testing
- The generator was run twice with identical output. It checks that all three themes define the same tokens. Every color field that the theme file uses was checked against the generated class.
- The Kotlin sources were **not compiled** in this environment (no JDK or Android SDK). The first build in a consuming app is the first compile check.
